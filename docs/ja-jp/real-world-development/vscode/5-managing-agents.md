GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更案を作り、ファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのため、ライトモードの切り替えも追加します。新しい会話を始める代わりに、進行中のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - 変更を承認するには **Keep** を選択します。
   - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更した作業セット全体を確認することもできます。

> [!NOTE]
> ツールの呼び出し (たとえばターミナルコマンドの実行) で許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは前の作業で変更したコンポーネント、スタイル、local storage の使用方法などのコンテキストを保てます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが以前の変更を調べ、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選びます。
4. エージェントの方針が希望と異なる場合 (たとえば、切り替えユーザーインターフェイス (UI) を意図しない形でリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示すると、最初からやり直すより早く作業できます。追加プロンプトで「Cascading Style Sheets (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のように調整を依頼したり、「トグルを 3 つにせず、既存の設定パネルにライトモードを追加する」のように軌道修正したり、「両方の切り替えにキーボードショートカットも追加する」のように範囲を広げたりできます。

## 作業セットをレビューする

変更を commit する前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による保存など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視し、各ファイルの編集を確認して承認または取り消し、コンテキストを保ったまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加プロンプトでセッション途中の作業を調整しました。

次は[次のレッスン][next-lesson]で、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
