我们先为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作流程，帮助我们用正确的方法构建所需功能。本课将从 GitHub 议题开始，遵循典型的智能体驱动开发流程：生成新功能、确认代码有效且行为符合预期，最后将其成功合并到项目中。

> [!NOTE]
> 后续功能工作将沿用同一会话。通常，不同文件类型的工作会使用不同会话或拉取请求 (PR)；这里采用简化方式，以便聚焦核心概念。

在本课中，你将：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续实现此功能时，你将更新存储库说明、自定义现有 `quality-checks` 技能、添加模型上下文协议 (MCP) 验证、创建质量保证 (QA) 智能体并打开功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访客需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但组合多个类别等细节需要在编码前确定。你将使用 Plan 模式明确这些决定，再授权 Autopilot 按界定好的范围实现功能。

## 背景

引入人工智能 (AI) 编码智能体不会改变开发的基本流程，反而使其更重要。多数开发人员会采用类似以下的流程：

1. 打开已创建的议题，查看具体需求。
2. 制定实现计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多与上述流程类似。

坚持这一常规流程，可确保 AI 生成的代码满足需求，并经过与手写代码相同的审查。

## 会话模式

**会话模式**控制智能体的自主程度。可以通过提示框下方的下拉列表设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是模板预置的议题，无需再创建。
2. 选择 **New session**，然后选择基于更新后的 `main` 创建 **new working tree**。

   ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，让智能体运行 `node --version` 和 `npm --version`。如果这些命令在终端中有效，但在会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划让你能在 Copilot 编写代码前审查实现方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送以下提示，并审查 Copilot 的计划：

1. 在提示框中输入并发送：

   ```plaintext
   Build this feature.
   ```

2. 回答 Copilot 的问题，并对照议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。
3. 确认计划使用项目现有工具运行 lint、单元测试、端到端 (E2E) 测试和类型检查，并将范围限定为实现和测试筛选功能；完成质量工作流后再创建 PR。
4. 批准计划前先提出所需更改，并保留议题 URL 及已达成共识的澄清内容，供后续验证。

## 明确批准 Autopilot

批准计划会授权 Copilot 开始实现，因此请先确认计划符合议题要求。

1. 选择 **Approve and implement this plan**，或当前版本中的等效选项。
2. 确认当前模式指示器显示 **Autopilot**。不要假定批准计划会自动切换模式。

> [!NOTE]
> 批准后 Copilot 可能立即开始实现，因此应先审查计划。Copilot 会按计划实现功能、生成代码并运行测试。

3. 如果 Copilot 报告缺少依赖项或端口冲突，先解决环境问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也需要在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已批准的澄清检查结果，包括多个类别及类别与发行商组合。确认更改遵循现有存储库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务器，也可能复用本地服务器；确认被测服务器属于当前工作树，而不是之前课程启动的服务器。

## 试用新功能

代码看起来没问题，但还需要确认能否运行。像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与该类别匹配。清除筛选，再选择一个发行商，确认结果与该发行商匹配。
4. 同时应用类别和发行商筛选，并根据议题和已批准的计划检查结果。如果支持多个类别，还要验证已确定的组合行为。
5. 尝试一个没有匹配游戏的筛选组合，检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，使用以下提示让 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。接下来的第 4 至第 8 课会继续使用此会话、工作树和分支。下一课将把自定义说明应用到筛选代码，然后添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。
